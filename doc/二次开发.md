## 项目架构速览

```
│
```

## 开发环境搭建

### 基础环境

```bash
# 克隆项目
git clone https://github.com/YOUR_USERNAME/FinSight.git
cd FinSight

# Python 虚拟环境
python3 -m venv venv
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 如果需要热重载调试，安装 watchdog（可选）
pip install watchdog
```

### 配置文件

```bash
cp .env.example .env
```

`.env` 填入 API Key。开发时建议打开调试日志：

```env
# 在 .env 中添加
LOG_LEVEL=DEBUG
```

然后修改 `app/core/glm_client.py` 顶部，添加：

```python
logging.basicConfig(level=os.getenv("LOG_LEVEL", "INFO"))
```

### 启动开发服务器

```bash
# 方式一：直接运行（推荐，自带 reload）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 方式二：从 main.py 入口
python app/main.py
```

`--reload` 模式下，修改 Python 代码会自动重启，但修改前端静态文件（HTML/CSS/JS）需要手动刷新浏览器。

```python
class Settings:

    GFZQ_TOKEN: str = os.getenv("GFZQ_TOKEN", "")

    def validate(self):

```

**二次开发要点：**

- 新增配置项：在 `Settings` 类中添加属性，在 `.env` 中添加对应变量
- `validate()` 方法只校验启动必需项，可选配置不要放这里
- 换 LLM 厂商：添加新的 API Key 字段（如 `OPENAI_API_KEY`），保留旧的做兼容

### app/core/glm_client.py — LLM 客户端核心

这是项目中最关键的模块，也是二次开发最常改动的文件。

**当前结构：**

| 函数/变量 | 职责 |
|-----------|------|
| `SYSTEM_PROMPT_FINANCE_WITH_TOOLS` | 带工具的金融对话系统提示词 |
| `SYSTEM_PROMPT_FINANCE_NO_TOOLS` | 无工具时的系统提示词 |
| `SYSTEM_PROMPT_VISION` | 图像分析系统提示词 |
| `MCP_SERVERS` | 广发证券 MCP 服务地址列表 |
| `_is_valid_token()` | Token 有效性检查 |
| `_build_mcp_tools()` | 构建 MCP 工具列表（格式依赖 Zhipu SDK） |
| `client` | 模块级 LLM 客户端单例 |
| `mcp_tools / has_mcp_tools` | 模块级工具状态 |
| `stream_finance_chat()` | 金融对话流式生成器 |
| `stream_vision_chat()` | 图像分析流式生成器 |
| `_sse_event()` | SSE 格式化 |
| `_friendly_error()` | 错误码转中文提示 |
| `ERROR_CODE_MAP` | 智谱业务错误码映射 |

**数据流：**

```
用户输入 → chat.py (校验参数) → glm_client.py (构建请求)
    → Zhipu SDK → 智谱 API
    → SDK 返回流式 chunk → yield SSE 事件 → StreamingResponse → 前端
```

### app/api/chat.py — API 路由

当前只有一个端点：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/chat/stream` | POST | SSE 流式对话，支持 finance/vision 两种模式 |

**请求体结构：**

```json
{
  "messages": [{"role": "user", "content": "..."}],
  "mode": "finance",
  "image_url": null,
  "thinking": false
}
```

### app/static/index.html — 前端单页应用

所有交互逻辑都在一个 HTML 文件中（无前端框架）：

| 区域 | 说明 |
|------|------|
| 左侧边栏 | Logo、模式切换、导航菜单、对话列表 |
| 中间对话区 | 消息流、欢迎页、输入框 |
| 右侧边栏 | 功能介绍卡片、快捷操作按钮 |
| 底部工具栏 | 图片上传、深度思考开关、发送按钮 |

**关键 JS 函数：**

| 函数 | 职责 |
|------|------|
| `switchMode(mode)` | 切换 finance/vision 模式 |
| `sendMessage()` | 核心：组装请求 → fetch SSE → 流式渲染 |
| `handleImageUpload()` | 图片上传与 base64 编码 |
| `toggleThinkingMode()` | 深度思考开关 |
| `addStreamingAiMessage()` | 创建流式消息 DOM 容器 |
| `renderMarkdown()` | marked + DOMPurify 渲染 |
| `newConversation()` | 新建对话 |
| 本地存储 | 对话记录保存在 localStorage |

**SSE 事件处理（sendMessage 核心逻辑）：**

```
fetch POST /api/chat/stream
  → reader 逐行读取
  → 解析 data: JSON
  → type=thinking → 写入思考区（可折叠）
  → type=content → marked 渲染到消息区
  → type=error   → 红色显示错误
  → [DONE]       → 结束
```

## 常见二次开发场景

### 场景一：更换 LLM 提供商

以切换到 OpenAI 为例：

**1. 修改 requirements.txt**

```txt
# 移除 zai-sdk，添加 openai
openai>=1.0.0
```

**2. 修改 app/core/config.py**

```python
class Settings:
    LLM_API_KEY: str = os.getenv("LLM_API_KEY", "")  # 通用命名
    LLM_BASE_URL: str = os.getenv("LLM_BASE_URL", "https://api.openai.com/v1")
    LLM_MODEL: str = os.getenv("LLM_MODEL", "gpt-4o")
    VISION_MODEL: str = os.getenv("VISION_MODEL", "gpt-4o")
    ...
```

**3. 新增 app/core/llm_client.py（替代 glm_client.py）**

```python
from openai import OpenAI

client = OpenAI(api_key=settings.LLM_API_KEY, base_url=settings.LLM_BASE_URL)

def stream_finance_chat(messages: list, thinking_enabled: bool = False):
    ...
    response = client.chat.completions.create(
        model=settings.LLM_MODEL,
        messages=full_messages,
        stream=True,
        # thinking 改为 OpenAI 的方式
        # ...
    )
    for chunk in response:
        delta = chunk.choices[0].delta
        # reasoning_content → OpenAI 返回的是 delta.reasoning
        ...
```

**4. 修改 app/api/chat.py 中的 import**

```python
from app.core.llm_client import stream_finance_chat, stream_vision_chat
```

**5. 前端调整（如需）**

OpenAI 的 `reasoning` 字段不同于 Zhipu 的 `reasoning_content`，SSE 事件格式保持一致即可。

**要点：**
- MCP 工具（`type: "mcp"`）是 Zhipu SDK 特有功能。如果新厂商不支持原生 MCP，需要改为 Function Calling 方式：将每个 MCP 工具声明为 `function` 类型，在本地写函数调用 MCP 服务获取数据，再将结果传回模型
- 可参考 `doc/zai-sdk.md` 了解当前 SDK 的用法差异

## 开发约定

### 代码风格

- **后端**：保持现有风格——无注释（遵循项目惯例），使用 `logger` 而非 `print`
- **前端**：原生 JS，无框架，DOM 操作为主

### SSE 事件格式

所有流式事件必须遵循统一格式，方便前端解析：

| type | content 含义 |
|------|-------------|
| `thinking` | 模型的思考/推理过程 |
| `content` | 最终回答文本 |
| `error` | 错误信息 |

```python
yield _sse_event({"type": "content", "content": "..."})
yield _sse_done()  # data: [DONE]
```

### 错误处理

- 通过 `_friendly_error()` 将错误码转为中文
- 连接断开类错误静默处理（只打 warning 日志）
- 其他错误 yield `error` 事件到前端

### 新增文件规范

```
app/
├── core/       # 核心逻辑：LLM 客户端、配置、工具类
├── api/        # API 路由：只做参数校验和分发
├── static/     # 前端文件
└── models/     # Pydantic 数据模型（如果多了可以拆分）
```

## 调试技巧

### 查看 SSE 原始数据

浏览器开发者工具 → Network → 找到 `/api/chat/stream` 请求 → Response 面板可以看到实时涌出的 SSE 数据。

或者用命令行模拟：

```bash
curl -N -X POST http://localhost:8000/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"你好"}],"mode":"finance"}'
```

### 模拟 MCP 工具调用

在 `.env` 中填入无效的 `GFZQ_TOKEN`，系统会自动降级为无工具模式，模型纯靠自身知识回答，方便调试 LLM 本身。

### 查看后端日志

```bash
uvicorn 运行时终端会输出所有 logger 信息，重点关注：

INFO:FinSight initialized: MCP tools enabled/disabled
INFO:Calling GLM API: model=glm-4.7-flash, tools=yes/no
```

### 前端调试

`index.html` 中有几个全局变量可以直接在 Console 中操作：

```javascript
messages        // 当前对话消息数组
currentMode     // 当前模式：'finance' | 'vision'
thinkingEnabled // 深度思考开关
conversations   // 全部对话列表
```

### 常用问题排查

| 现象 | 排查方向 |
|------|---------|
| 页面白屏 | 检查终端是否有 Python 报错；检查 `static/` 路径是否正确 |
| API 返回 422 | 请求体格式不对，检查 `ChatRequest` 模型定义 |
| SSE 连接断开 | 智谱 API Key 是否有效、账户是否欠费、网络是否稳定 |
| 工具调用失败 | `GFZQ_TOKEN` 是否有效、广发证券 MCP 服务是否可用 |
| 前端不渲染 | 检查 Console 是否有 JS 错误；检查 SSE 事件格式是否正确 |
| 图片上传无反应 | 检查图片大小是否过大；检查 `glm-4v-flash` 模型是否可用 |
